## 一键启动和停止

在项目根目录双击[启动助理.cmd](../启动助理.cmd)，打开“个人研究与日程助理”控制台，然后点击“启动助理”。准备完成后自动打开 `http://127.0.0.1:8501`，无需分别维护两个终端。

- 默认只允许本机访问。需要手机接入时，启动前勾选“允许安卓手机通过局域网接入后端”。网页界面仍只在电脑本机打开。
- 已有 `local-data/module01_tasks.sqlite3` 时沿用该业务库及 `module01_memory.sqlite3`；否则使用 `assistant.sqlite3` 与 `assistant_checkpoints.sqlite3`。不会为启动界面清空旧数据。
- 如果8002或8501已被之前的终端占用，控制台会提示，不会接管或结束别的进程。可以打开原界面；要改用一键启动，先在原启动终端按 `Ctrl+C` 停止对应服务。
- “停止本次服务”只停止本控制台创建的进程。关闭控制台时可选择停止并退出，或保持运行并最小化。电脑休眠、关机或服务停止期间不会即时弹提醒。
- 启动日志保存在 `local-data/logs/`。环境检查可单独运行，检查本身不连接模型或邮箱：

```powershell
.\.venv\Scripts\python.exe -X utf8 .\start_assistant.py --check
```

本机已经配置的DeepSeek与QQ邮箱参数继续使用。授权码、API Key和手机配对令牌保留在本机，不需要发送到聊天。全新环境先按[依赖文件](../requirements.txt)安装；完整版本锁见[requirements.lock.txt](../requirements.lock.txt)。根锁当前97包，新增二维码生成依赖。

## 七个页面怎样使用

| 页面 | 可进行的操作 |
|---|---|
| 消息与日程 | 直接粘贴消息并上传附件；按类别、重点联系人、标签筛选和搜索；分页查看原文、摘要、附件和事项；明确设置发送者角色；完成或取消事项，纠正标题、地点、时间、类别、摘要和多个标签；查看修订历史 |
| 研究资料 | 上传txt、md或含文本PDF；检索原文并基于证据问答；下载原件；明确点击正文分类，查看分类依据的页码与逐字引用；人工纠正文件类别和标签 |
| 提醒与角色 | 设置截止/活动提醒规则，查看与取消提醒；管理精确发送者角色；查看QQ邮箱状态并明确执行同步 |
| 重点收件箱 | 查看重要联系人新消息到达记录；单独设置弹窗与提示音、新鲜度窗口；明确标记已读 |
| 手机接入 | 启用专用通知入口、生成或轮换配对令牌；用二维码下载安装APK和配对；查看设备与上传队列状态 |
| 运行追踪 | 查询Trace，查看执行节点、耗时、状态和安全错误类型，定位失败环节 |
| 对话助理 | 用自然语言查询、记录或完成事项，查询研究资料；同一界面会话沿用thread_id，明确新建对话才换号 |

首次打开页面的读取操作不应触发模型分析、文件写入或邮箱同步。模型分析、分类、问答、导入、修改、手机配对和同步都有明确按钮或表单提交；已启用的后台邮箱与通知队列则按已保存配置运行。

## 消息、角色与人工纠正

展开“粘贴消息并整理附件”即可录入，无需编写JSON。填写原消息发送日期与钟点；确实刚收到时可以明确选择使用当前北京时间。输入你确定的联系人标识和消息正文，选择附件后提交。相同原消息重试使用稳定来源标识，部分附件失败会保留消息编号及已成功步骤；真正开始录入另一条消息时点击“开始录入下一条消息”。高级JSON导入仍保留。

角色由你确定。在消息卡片展开“设置这个发送者的角色与重要程度”，填写“导师”“招聘人员”等你确认的角色，再保存。匹配依赖来源、账号和发送者标识；系统不会因昵称含“老师”就自行认定导师。

类别为研究、学生生活、求职、其他；多个标签用于进一步组织，例如“组会、论文、报销”。消息和文件可以分别纠正类别与标签。人工纠正保存版本及历史，原消息、原件和最初提取证据继续保留；并发修改发生版本冲突时应刷新后重试。

事项支持待办、已完成和已取消；正式HTTP接口和Agent查询一致，已取消不计作已完成，也不能直接执行完成操作。更正时间、地点或状态会取消关联的旧未投递提醒；勾选重新安排后，按当前规则为仍待办且时间有效的事项重建计划。已交给系统通道的通知无法撤回，不能把“取消提醒”理解为撤销已经显示的弹窗。

## 时间、地点与两种提醒

截止、活动时刻/区间和地点同时使用文字与颜色区分。时间计算以原消息发送时间换算后的北京时间为基准，裸“周三”按该消息所在自然周计算，即使已经过去也不顺延下周。

| 原文明确的信息 | 保存结果 |
|---|---|
| 10月20日、周三前 | 日期及时间性质；没有`at`，不补零点或23:59 |
| 2026年10月20日15:00 | 精确到分钟的`at`，带`+08:00` |
| 10月20日至22日 | `start_date/end_date`，保留首末日期 |
| 明天15:00到17:00 | `start/end`，两端均带日期和时区 |
| 信息不足、非法日期、倒置或混合精度区间 | 保留原话并标为待确认 |

日期省略年份时采用原消息北京时间年份，不因为已过去就猜下一年。明确写出UTC偏移的完整时刻会转换为北京时间；未明确的海外时区、农历与重复规则不强行解析。

**截止/活动提醒**在“提醒与角色”中启用。分钟级区间按起点提前提醒；日期级事项或日期区间必须由你设置日期提醒钟点，原事件的日期精度保持不变。新自动计划跳过过期事项和已过提醒时间；投递前还会检查旧自动队列，避免历史邮件重新弹提醒。显式手工计划可以保留补发。

**重点联系人到达提醒**在“重点收件箱”单独启用。新的重点消息进入收件箱，按新鲜度规则决定是否弹窗并提示音；旧消息不会为此补发。已读状态由明确操作更新。`submitted`只表示通道已接收，不表示你已经看到、读过或系统一定只显示一次。Windows通知是否显示、提示音是否可听还受系统通知和声音设置影响。

## 文件原件、正文分类与问答

消息中的文件名先作为附件线索。只有获得真实字节后，详情才标记原件可用，并允许按消息与附件序号下载。可以在消息卡片补传真实原件；原件归档支持任意格式、单件最多25MB，不执行附件。

正文解析、自动正文分类和RAG支持单件不超过10MB的txt、md、含文本PDF。扫描PDF暂不支持OCR；docx、zip等原件可以保存和下载，但当前不会因此获得正文解析能力，可以人工设置类别和标签。

“读取正文并分类”使用真实提取正文，返回类别、标签与逐字证据。若文件过长只读取节选，界面显示读取覆盖范围。分类证据通过出处校验不代表语义判断永远正确；保留人工纠正入口。

问答先从本地BGE中文Embedding与Qdrant索引检索片段，再请求DeepSeek生成带引用的回答。引用展示文件、页码与原文；证据不足时返回未知。第一次建立索引可能需要下载本地Embedding模型。两篇参考论文的文件名或合成笔记不能当作已取得真实论文。

## QQ邮箱

已有配置无需重复填写。首次配置使用[configure_mail.py](../configure_mail.py)，在本机按提示开启IMAP并填写授权码；配置变化后重启服务。读取使用只读IMAP与PEEK，原邮件、UID游标和处理队列持久化，失败按有限退避重试，不发送邮件。

“提醒与角色”提供邮箱状态及明确同步操作；已启用的后台邮箱按配置轮询。真实附件原件与可解析文档分别归档、建立索引，不能把下载成功当作分类或问答成功。

[本轮QQ只读检查](results/qq_delivery_check.json)实际读取两封非空正文，并在重新连接后验证无新信时不重复导入；耗时分别约1.398秒和0.487秒，只代表请求耗时。现有75封本地归档暂未找到可用于本轮附件验收的真实附件；新附件原件取得、真正新信增量及从收到到弹窗的延迟闭环仍待验证。代码测试与合成MIME不能替代真实QQ全链路验收。

## 安卓手机：无线安装与配对

1. 电脑和手机连接同一可互通Wi-Fi；在启动控制台勾选允许手机局域网接入后启动。
2. 电脑网页打开“手机接入”，明确启用并保存配对信息。页面提供手机能访问的电脑地址、APK下载二维码和私有配对二维码。
3. 手机浏览器扫码下载[已构建APK](../android-notification-bridge/dist/student-assistant-bridge.apk)，由你确认安装；安装后扫描配对码，核对地址并保存配置。
4. 由你在安卓系统设置中授予通知使用权，选择微信、QQ、BOSS直聘的采集范围并启用。配对二维码不会自动授予系统权限。扫码工具不能识别配对链接时可手工填写页面给出的地址和令牌。
5. 可以使用应用的合成测试通知检查连接状态。日常运行无需USB；电脑停止或网络断开时，手机先缓存，恢复可达网络后补传。

手机需Android 8.0及以上。通知摘要可能缺少全文、原消息时间和稳定发件人身份；出现文件名不等于获得附件。来源应用明确提供消息时间戳时采用该字段；否则默认不把通知发布时间当成原聊天发送时间来自动计算相对日期。页面提供显式近似时间选项，聚合摘要仍不自动据此建时间提醒。

离线队列有容量限制，满后会显示丢弃数量；安卓省电和后台限制可能延迟上传，不能承诺所有机型秒级实时。离开同一Wi-Fi后若要持续上传，需要另行提供经过认证与TLS保护的可达地址；本项目没有替你部署公网服务。默认留在本地缓存，USB不是运行依赖。

APK编译、对齐与签名验证已有记录；当前无可用安卓设备，**安装、系统授权、真实三应用通知和机型后台行为尚未实机验证**。详细协议、容量和来源见[通知接入说明](CHANNEL_INTEGRATION.md)，构建结果见[build_result.json](../android-notification-bridge/dist/build_result.json)。

## 数据、恢复与运行边界

- 本机资料主要保存在`local-data/`：双SQLite、消息和队列、附件原件、EML、Qdrant索引及模型缓存。备份或移动时先停止对应服务，再整体备份相关数据目录与本机配置；不要只复制一个数据库而遗漏原件和向量文件。
- Trace保存运行元数据，不保存消息正文、Prompt、参数或凭证。分析失败保留原文及安全错误类型，可据Trace定位；模型处理成功不等于内容判断正确。
- Qdrant local按单后端进程使用。一键启动与原终端不要同时操作同一组数据。
- 手机令牌仅用于专用通知入口；令牌或二维码泄露后可以明确轮换。电脑管理界面和其他业务接口保持本机访问。局域网HTTP不提供传输加密，不把它当作公网部署方案。
- [Dockerfile](../Dockerfile)和[Compose](../compose.yaml)已准备，本机缺少Docker CLI，只有静态检查；没有镜像构建或容器运行成功证据。Linux容器也不能直接提供本机Windows桌面通知。
- 根Git已进行公开发布整理，提交与远端上传状态见[发布记录](PUBLICATION.md)。上游源码快照的完整原版demo与全部依赖未运行；本交付使用其中的独立`student`服务配置。

[最终报告](results/final_delivery.json)已汇总回归、实际HTTP、模型、文档、重启与邮箱验证；设备或环境缺失造成的未验证项继续保留，不用“100%”覆盖这些边界。
